FLAGS
  F1. controllerTEB requires R2023a+ and is NOT available at R2022a
      (https://www.mathworks.com/help/nav/ref/controllerteb.html). Any contract
      path depending on TEB (e.g. lidar_react opts) must fall back to
      plannerRRTStar/mobileRobotPRM replanning + controllerPurePursuit tracking
      (all R2022a-safe), or the baseline must be raised to R2023a+. FAIL CLOSED.
  F2. robotScenario, robotPlatform (+move) and robotLidarPointCloudGenerator
      are all introduced in exactly R2022a: R2022a is the minimum viable
      release. State "R2022a minimum", not "any recent release".
  F3. controllerPurePursuit output semantics changed in R2026a. Verbatim from
      the official Version History
      (https://www.mathworks.com/help/robotics/ref/controllerpurepursuit-system-object.html):
        "R2026a: MaxAngularVelocity renamed to MaxCurvature - The
         MaxAngularVelocity property is now called MaxCurvature."
        "R2026a: angvel output argument renamed to curvature - The angvel
         output argument is now called curvature."
      CONSEQUENCE: on R2026a+ the second output is CURVATURE, NOT angular
      velocity. Feeding it to a robot as angular velocity is wrong. For
      R2022a target code: use MaxAngularVelocity and treat output 2 as
      angular velocity. For R2026a+: omega = curvature * desiredLinearVelocity.
      Any cross-release code must branch on version or convert explicitly.
  F4. checkCollision self-collision defaults changed in R2022b (see row 11).
  F5. ROS link target corrected to ROS 2 Jazzy + Gazebo Harmonic. The ROS 2
      MATLAB APIs (rows 14-17) are OK at R2022a, so the optional link is
      baseline-compatible - but it remains NOT BUILT/NOT EXECUTED (gated OFF).
      ROS 1 (rosinit) guidance removed; ROS 1 does not apply to this repo.
      The repo launcher pins ROS_AUTOMATIC_DISCOVERY_RANGE=LOCALHOST, so the
      link expects MATLAB on the same host (README-verified).
